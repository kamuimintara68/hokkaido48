## 監査結果と修正

| 目的 | 監査で見つかった問題 | 修正後の動作 |
|---|---|---|
| 別Tripへの二重登録を防ぐ | 旧処理は同じTrip内のファイル名だけで置換し、別Tripへの登録を制限しない | 全TripのGPX資料を照合し、同じGPXが他Tripにあれば保存しない。同じTripは再解析・置換を許可。新規取込では座標と時刻のSHA-256識別値を保存し、名前変更にも対応 |
| 全線への自動昇格を止める | 88%以上と端点条件で全線に昇格し、走っていない欠けも国道全線geometryで埋める | 全線候補の表示だけ残す。保存する状態は一部走破、一致geometryだけを保存。route-statusでの人による全線確定は維持 |
| 読込前の解析を止める | 路線一覧の非同期読込が終わる前に解析できる | 読込完了まで解析を無効化。解析中はファイル・Trip変更と保存も無効化。路線/地図読込失敗時は古い候補を保存できない |
| 保存失敗で既存記録を壊さない | 保存前に自動バックアップを削除し、対象外Tripのgeometryも一括書換えする。保存後の検証失敗でも復元しない | バックアップ削除と一括geometry変更を撤去。全保存内容を読戻し比較し、検証失敗時は直前のTripデータに復元。読めない既存データや別画面の更新は上書きしない |

新しい確認履歴にはgeometryを重複保存せず、正本は既存形式の `routeSegments.confirmedGeometry` に保持します。対象Trip内の別GPX、音声等の資料、無関係な旧geometryも保持します。

## 残るリスク・反映条件

1. iPhone/iPad実機のSafari、端末容量、キャッシュは未検証。スマホ幅のChromiumテストは実機確認の代用ではありません。
2. 古いGPX資料には識別値がないため、点数・距離・開始終了時刻、またはファイル名/サイズで照合します。完全な同一性を保証できず、時刻のない旧GPXを名前変更した場合などは検出できないことがあります。Web Cryptoを利用できないHTTP環境でもこの照合へ戻ります。
3. バックアップを削除しないので、容量に余裕がなければ保存を中止します。既存データの圧縮移行や削除による空き容量確保は行いません。
4. 書込後検証と復元の両方がブラウザ障害等で失敗した場合、完全復元を保証できません。自動復元未完了を明示して停止します。複数タブの同時書込を完全に排他する構造変更は行っていません。
5. 既存Tripの自動全線判定を一括で取り消す処理はありません。今回の再解析対象だけが一致区間の一部走破に置換され、人がroute-statusで確定した全線状態は保持されます。
6. HTMLのキャッシュ識別子は変更していません。本番反映時は旧GPXコードがキャッシュに残らない方法を決める必要があります。

本番反映の承認前に停止しています。承認後もmain全体のマージや19Trip/クラウドの上書きではなく、Build84へ検証済みJSの差分だけを反映することが前提です。

## 再実行方法

Node.jsとPlaywright用ブラウザを用意し、リポジトリの `tests` ディレクトリで実行します。

```powershell
npm ci
npx playwright install chromium
npm test
```

標準では合成GPXによる11本を実行します。実GPXテストも実行する場合は、無視対象の `tests/private-fixtures/20260927.gpx` と `tests/private-fixtures/backup-19.json` にファイルのコピーを配置します。元ファイルには書き込みません。

任意のファイル位置を使う場合：

```powershell
$env:GPX_FIXTURE = '実GPXの絶対パス'
$env:GPX_BACKUP = '19Tripバックアップの絶対パス'
npm test
```

既存のChromium実行ファイルを使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE` にその絶対パスを設定できます。今回の実行環境では標準ブラウザ配布先のダウンロードに失敗したため、別途取得したChromium 153を使用しました。Playwright 1.62.1、Leaflet 1.9.4を固定しています。

将来の有限プロジェクトでも、正本固定→最小差分→実データを使う独立環境の回帰テスト→合格で開発停止→利用へ戻る、という手順を再利用できます。
